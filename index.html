Senior Design: OSCAR

Open Source Copter for Academic Research · Team sddec26-05 · Spring 2026 to Fall 2026 · Team of 7 · My role: Hardware Lead · Advisor: Dr. Nathan Neihart

Description

My senior design project is OSCAR (Open Source Copter for Academic Research). The purpose of this project is to create an open-source, easily accessible platform for learning about and performing research with quadcopters. The main deliverables include a working prototype of a drone flight controller and electronic speed controllers for the motors which fit on a standard 5-inch drone frame.

My Role

My main role on the team was to lead the design of the electronic speed controllers (ESCs) for the quadcopter brushless DC (BLDC) motors. The skills I performed included research, schematic design, part selection/specification, PCB layout, board fabrication/ordering, and PCB assembly. I also helped to interface the hardware with the firmware team so that we could have functional control of the BLDC motors from the flight controller.

Skills and Knowledge Gained

Through this project, I gained experience with high-density layout, multilayer board routing, signal integrity, and power handling on a printed circuit board (2oz copper). I also honed my craft when it came to documentation and readability. Because this project is open source, I had to explain every single design choice made during the design process so that anyone who wanted to recreate the board/circuits or who wanted to learn about the design of an ESC could understand my process. It is for the same reason that it is very important that my design is readable and clear in its presentation.

Supporting Documents

  • OSCAR Docs Project documentation website
  • Team website sddec26-05.sd.ece.iastate.edu
  • Final Design Document PDF, 87 pages
  • Faculty Panel Presentation PDF slides, shown below

Big-Picture Contribution

In recent years, drones have become a point of interest for many. Specifically, rotary-wing quadcopter drones have the potential to solve complex problems that couldn't be solved otherwise. For example, a research team may want to find a way to build a drone platform that can test water samples remotely in hard-to-reach areas. If a research team wanted to do this now, they would have to start from scratch and spend many months learning how drones work and how they would go about building one. Our project makes this simple for such a team, as they can look through all of our open-source deliverables and build upon them to add their own sensors/devices. The baseline for software, hardware, and firmware development and implementation has already been laid out for them, saving time and money for the team.

Infrared LED Transmitter

EE 230: Electronic Circuits II · Spring 2025 · Lab partner: Matt Smith

Description

We designed an optical signaling device capable of working from over 20 feet away to turn two separate LEDs on and off. The project included designing an oscillator on the transmitter remote, which we powered with a 9V battery. For the receiver, we designed precise second-order band-pass filters for detecting the specific frequencies that we were transmitting from the remote. The received signal was rectified and amplified to power LEDs on the receiver.

My Role

My lab partner, Matt Smith, and I designed, built, and tested each part of the device together. I used my knowledge of circuits to tweak our circuit components in the required ways to tune our band-pass filters exactly to the desired frequencies.

Skills and Knowledge Gained

This project taught me about analog circuit design, including op-amp design, second-order filtering, transimpedance amplifiers, rectifiers, and LED luminosity curves. On the soft skill side, I learned how to use technical writing to convey our design. This included IEEE writing style, proper picture captioning, and concise explanations of design choices.

Resources Used

I used tools such as SPICE software, MATLAB for calculations and simulations, an Iowa State University-specific tool called Loopinator for Bode plot generation, and other lab equipment such as oscilloscopes and DMMs.

CyBot

CPRE 288: Embedded Systems · Team project

Description

We programmed a robot to navigate a maze environment without being able to see the obstacles. The robot was controlled remotely using a PC over Wi-Fi. The robot could move around following our keyboard commands and could “see” through the sensors it had on board.

My Role

I built code to take in ultrasonic sensor data and find exactly where all objects inside the scan are located and how far away they are. The scan also used infrared sensors as a secondary measurement device to make the scan more robust through redundancy. The Python GUI and socket/client connection were the things I worked on most for the team. The GUI involved creating objects where they are detected and using my knowledge of trigonometry and geometry to ensure these objects are accurate. The program needed to remember the locations of all objects found and plot the course of our robot. I also created a simple and intuitive control scheme for the user to communicate with the robot.

Skills and Knowledge Gained

I learned embedded-level C design, including reading through microcontroller datasheets for how to use the different MCU functions available. I learned how to work with a team to define a project, from initial conception to final design requirements and validation. I also learned how to take suggestions from the team and get feedback from the implementations.

Resources Used

I used a Tiva microcontroller, the C programming language, Git for revision control, and Python for the GUI.

Pipelined RISC-V Processor

CPRE 381: Computer Organization and Assembly Level Programming

Description

We created a working single-stage processor and a 5-stage pipelined processor based on the RISC-V instruction set architecture. The lab project involved designing each stage one by one and testing it as the lab continued.

My Role

I created the VHDL code to make the processors function. I created various components for the processor, such as the arithmetic logic unit, pipeline control unit, and data hazard detection. For validating functionality, I wrote test benches in VHDL and analyzed the simulated waveforms. I also used assembly language to feed instructions in order to test the full functionality of the processor.

Skills and Knowledge Gained

I learned how a processor works and the stages of a pipelined processor. I learned how to write assembly code for testing our processor. I learned how to program in VHDL for designing the processor and also for the test benches we used to validate our design. All of this validation and testing taught me the importance of being thorough and testing at each step along the process of engineering design.

Resources Used

I used the software Quartus Prime and QuestaSim. In this lab, I got experience with using VS Code as an all-purpose IDE. I used VS Code to write assembly code and VHDL code for both the final design and all of the test benches.
